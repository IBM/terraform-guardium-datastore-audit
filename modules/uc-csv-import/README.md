# Universal Connector CSV Import

This module imports any Universal Connector profile CSV file into IBM Guardium Data Protection and deploys every profile it contains on the specified collector(s). It is datastore-agnostic — it does not configure the underlying data source. Use it when you already have a profile CSV (exported from Guardium, hand-crafted, or generated by another tool) and want to register and deploy it via Terraform.

**Profile names are extracted automatically from the CSV** using Terraform's built-in `csvdecode()` function — you do not need to provide them separately. A single CSV with multiple profiles will have each one imported and deployed individually.

**Supported Versions:** This module requires IBM Guardium Data Protection (GDP) version **12.2.1 and above**.

## Prerequisites

Before using this module, you need to:

1. **Valid profile CSV**: A Guardium Universal Connector profile CSV file that is ready to import. All UC input types are supported (CloudWatch, SQS, Kafka, JDBC, Filebeat, etc.).
2. **Guardium Data Protection**: A running GDP instance (version 12.2.1 or above).
3. **Guardium OAuth Client**: Register an OAuth client via `grdapi register_oauth_client` to obtain `gdp_client_id` and `gdp_client_secret`.
4. **Guardium Credentials**: A Web UI user with permissions to import profiles and install connectors.

## How it works

```
CSV file on disk
      │
      │  csvdecode()  — parse header row, extract "name" column from every data row
      ▼
local.profile_names  =  set of connector names found in the file
      │
      ├─ local_file.csv_temp          write CSV to .terraform/ for multipart upload
      ├─ authentication               OAuth login → access token
      ├─ import_profiles              POST /restAPI/importProfilesFromFile  (all profiles at once,
      │                               connection tests run here when test_connections = true)
      └─ install_connector [for_each] POST /restAPI/bulkInstall  (one call per profile name,
                                      skipped for profiles whose connection test failed)
```

## Features

- **Zero-config name extraction**: `csvdecode()` reads the `name` column from the CSV at plan time — no `udc_name` variable needed.
- **Multi-profile support**: A CSV containing multiple profiles imports and deploys all of them in a single `terraform apply`.
- **Partial deployment on failed connection tests**: If a profile's connection test fails on import (for example, bad credentials), it is reported as a warning and skipped, and every other profile is still deployed. `skipped_profiles` lists what was not deployed.
- **Datastore-Agnostic**: Works with any valid UC profile CSV regardless of input type.

## Usage

```hcl
module "uc_csv_import" {
  source = "IBM/datastore-audit/guardium//modules/uc-csv-import"

  # One or more UC profile CSV files — names extracted automatically from each
  csv_file_paths = [
    "/path/to/aws-postgres-profile.csv",
    "/path/to/snowflake-profile.csv",
  ]

  # Guardium Data Protection
  gdp_server        = var.gdp_server
  gdp_port          = "8443"
  gdp_username      = var.gdp_username
  gdp_password      = var.gdp_password
  gdp_client_id     = var.gdp_client_id
  gdp_client_secret = var.gdp_client_secret
  gdp_mu_host       = var.gdp_mu_host
}
```

## Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|:--------:|
| csv_file_paths | List of paths to UC profile CSV files to import into Guardium | `list(string)` | n/a | yes |
| gdp_server | Hostname/IP address of Guardium Central Manager | `string` | n/a | yes |
| gdp_port | Port of Guardium Central Manager | `string` | `"8443"` | no |
| gdp_username | Username of Guardium Web UI user | `string` | n/a | yes |
| gdp_password | Password of Guardium Web UI user | `string` | n/a | yes |
| gdp_client_id | Client ID from `grdapi register_oauth_client` | `string` | n/a | yes |
| gdp_client_secret | Client secret from `grdapi register_oauth_client` | `string` | n/a | yes |
| gdp_mu_host | Comma-separated list of Guardium Managed Units to deploy profile | `string` | `""` | no |
| enable_universal_connector | Whether to enable profile import and deployment | `bool` | `true` | no |
| test_connections | Test connections after import for profiles that support it (Kafka Connect-based, UC 2.0); other profiles are ignored. A failed test does not fail the apply: the profile is skipped (not deployed) and the others are still deployed | `bool` | `true` | no |

## Outputs

| Name | Description |
|------|-------------|
| profile_names | Set of all Universal Connector profile names extracted from the CSV files, including any that were not deployed |
| deployed_profiles | Set of profile names that were deployed on the collector(s) |
| skipped_profiles | Set of profile names that were NOT deployed because their connection test failed on import |
| csv_file_paths | List of CSV file paths that were imported |

## Troubleshooting

### Import fails with an authentication error
- Verify `gdp_client_id` and `gdp_client_secret` match the output of `grdapi register_oauth_client`.
- Ensure the Guardium Web UI user has the `Manage Universal Connector` permission.

### Install fails with "connector not found"
- This means the name in the CSV's `name` column does not match any imported profile. Confirm the CSV is well-formed and has a `name` header column.

### `csv_file_path` not found
- The path is evaluated relative to the directory where `terraform apply` is run. Use an absolute path or `"${path.module}/relative/path.csv"` to avoid ambiguity.

### Multi-profile CSV — only some profiles appear in Guardium
- All profiles are imported in one shot. Each one is deployed via a separate `install_connector` call keyed by the name in the `name` column. Check that all names in the CSV are unique.
