# UC CSV Import

This example imports one or more Universal Connector profile CSV files into IBM Guardium Data Protection and deploys every profile on the specified collector(s). It works with any UC input type (CloudWatch, SQS, Kafka, JDBC, Filebeat, and others).

## Prerequisites

Complete these steps in Guardium before running `terraform apply`:

1. **Register an OAuth client** on the Central Manager:
   ```
   grdapi register_oauth_client client_id=client1 grant_types=password
   ```
   Use the output `client_id` and `client_secret` as `gdp_client_id` and `gdp_client_secret`.

2. **Create a credential** in the Guardium UI under **Setup > Tools and Views > Universal Connector > Credentials** for any profile that requires one (e.g. an AWS credential for CloudWatch/SQS profiles, or a username/password credential for JDBC Connect profiles like Snowflake). The credential name must match the `credential_name` column in your CSV.

3. **Upload the JDBC driver JAR** (UC 2.0 JDBC Connect profiles only — e.g. Snowflake). In the Guardium UI go to **Setup > Tools and Views > Universal Connector > Upload Files** and upload the JAR. The filename must match the `jdbc_driver_library` column in your CSV (e.g. `snowflake-jdbc-3.13.30.jar`).

4. **Ensure a Kafka cluster is attached** to Central Manager (UC 2.0 Kafka-based profiles only).

## Usage

1. **Get a CSV template.** In the Guardium UI, go to **Manage > Universal Connector > Datasource Profile Management**, choose **Actions**, then **Download Profile Template**. Fill in the downloaded template with your profile details (the `name` column of each row becomes the connector name).
2. Copy `terraform.tfvars.example` to `terraform.tfvars` and fill in your values.
3. Set `csv_file_paths` to a list of one or more UC profile CSV file paths.
4. Run:

```bash
terraform init
terraform plan
terraform apply
```

After `apply`, the `deployed_profiles` output shows every connector that was deployed, and `skipped_profiles` shows any that were not because their connection test failed on import (each also produces a warning). Failed connection tests do not stop the other profiles from being deployed.

## When to use this example

- You have an existing UC profile CSV (exported from the Guardium UI, generated by another module, or hand-crafted) and want to register it without writing a custom module.
- You are migrating profiles from one Guardium instance to another.
- Your CSV contains multiple profiles and you want all of them deployed in one run.
- You are testing a new CSV profile before wiring it into a purpose-built datastore module.

## Variables

| Name | Description | Required |
|------|-------------|:--------:|
| csv_file_paths | List of paths to UC profile CSV files (names extracted automatically from each) | yes |
| gdp_server | Hostname/IP of Guardium Central Manager | yes |
| gdp_port | Port of Guardium Central Manager (default: `"8443"`) | no |
| gdp_username | Guardium Web UI username | yes |
| gdp_password | Guardium Web UI password | yes |
| gdp_client_id | OAuth client ID from `grdapi register_oauth_client` | yes |
| gdp_client_secret | OAuth client secret from `grdapi register_oauth_client` | yes |
| gdp_mu_host | Comma-separated Managed Unit hostnames to deploy the profile to | no |
| enable_universal_connector | Set to `false` to skip import and deployment | no |
| test_connections | Test connections after import for profiles that support it (Kafka Connect-based, UC 2.0); other profiles are ignored (default: `true`). A failed test does not fail the apply: the profile is skipped and the others are still deployed | no |

## Outputs

| Name | Description |
|------|-------------|
| profile_names | Comma-separated string of all connector names extracted from the CSV files, including any that were not deployed |
| deployed_profiles | Comma-separated string of connector names that were deployed on the collector(s) |
| skipped_profiles | Comma-separated string of connector names that were NOT deployed because their connection test failed on import (empty if none) |
| csv_file_paths | Comma-separated string of the CSV file paths that were imported, in the order given |
